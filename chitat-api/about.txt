# Описание проекта Chitat-API

## Общая информация

Chitat-API — это серверное RESTful API-приложение для платформы чтения, разработанное на Node.js с использованием TypeScript, Express и MongoDB (через ODM Mongoose). Проект предоставляет универсальный механизм работы с данными через динамическую генерацию запросов на основе метаданных схем.

## Архитектура проекта

Проект построен по модульной архитектуре с чётким разделением ответственности:

- **Core (ядро)** — базовые компоненты системы (Query, SchemaVault, Logger, SendData)
- **Config (конфигурация)** — настройки, схемы, типы, маршрутизаторы
- **Models (модели)** — определение схем MongoDB и бизнес-логики для сущностей
- **Routers (маршрутизаторы)** — обработка входящих HTTP-запросов

## Основные сущности предметной области

Система управляет следующими сущностями:
- Книги
- Пользователи
- Авторы
- Коллекции
- Классы/Группы
- Подписки
- Комментарии

## Принцип работы Query.ts

Query.ts — это центральный компонент системы, реализующий универсальный Query API для выполнения операций CRUD (Create, Read, Update, Delete) над любыми зарегистрированными сущностями без необходимости написания индивидуальных обработчиков для каждой модели.

### Ключевые возможности

1. **Динамическое определение модели**
   - Модель определяется из URL-параметра запроса
   - Проверка существования модели в реестре схем
   - Автоматическое применение соответствующей схемы Mongoose

2. **Гибкая система запросов**
   - Поддержка простых запросов (фильтрация по полям)
   - Поддержка сложных агрегационных запросов через MongoDB Aggregation Pipeline
   - Возможность использования кастомных билдеров запросов для специфичной логики фильтрации

3. **Автоматическое связывание данных (Populate)**
   - Автоматическое определение полей со ссылками на другие коллекции
   - Выполнение операции $lookup для присоединения связанных документов
   - Преобразование массивов в одиночные объекты для не-массивовых ссылок

4. **Система проекций (Screen)**
   - Выборочное получение только необходимых полей
   - Поддержка включения (+) и исключения (-) полей
   - Вычисление вычисляемых полей на лету

5. **Обработка файлов**
   - Загрузка файлов через multipart/form-data
   - Сохранение файлов в структурированные директории
   - Автоматическое связывание путей к файлам с документами

### Методы API

- **schemas()** — возвращает список всех зарегистрированных схем с метаданными
- **schema(req)** — возвращает детальное описание конкретной схемы
- **query(req)** — выполняет чтение данных (SELECT)
- **mutation(req)** — выполняет создание или обновление данных (INSERT/UPDATE)
- **delete(req)** — выполняет удаление данных (DELETE)

### Алгоритм обработки запроса

1. Извлечение имени модели из параметров запроса
2. Поиск модели в реестре схем
3. Парсинг тела запроса (query, screen, файлы)
4. Применение билдеров запросов (если определены)
5. Формирование финального фильтра
6. Для агрегаций — построение конвейера MongoDB
7. Выполнение запроса к базе данных
8. Формирование и возврат ответа

## Принцип работы SchemaVault.ts

SchemaVault.ts — это центральный реестр схем, который управляет регистрацией, хранением и предоставлением метаданных всех моделей данных в системе.

### Назначение

1. **Единый источник истины о схемах**
   - Централизованное хранение информации о всех моделях
   - Устранение дублирования определений схем

2. **Автоматическое извлечение метаданных**
   - Анализ схемы Mongoose и извлечение информации о полях
   - Определение типов данных, обязательности, связей
   - Выявление полей, исключённых из стандартного выбора

3. **Регистрация моделей**
   - Метод register() для добавления новых схем в реестр
   - Поддержка дополнительной информации (иконки, заголовки)
   - Поддержка кастомных билдеров запросов

### Структура данных реестра

Каждая зарегистрированная схема содержит:
- **info** — метаданные для отображения (иконка, заголовок)
- **model** — ссылка на модель Mongoose
- **fields** — плоская карта полей с их характеристиками
- **_builds** — карта функций-билдеров для кастомной логики запросов
- **_select_ignore** — список полей, игнорируемых при стандартном выборе

### Автоматический анализ полей

При регистрации схемы происходит автоматический анализ:

1. **Определение типа поля**
   - Базовые типы Mongoose преобразуются в унифицированный формат
   - ObjectID нормализуется к ObjectId
   - Определяются массивы и их внутренние типы

2. **Определение характеристик**
   - Обязательность поля (required)
   - Перечисления (enum)
   - Ссылки на другие коллекции (ref)
   - Файловые поля (file)
   - Пользовательские метаданные (about)

3. **Исключение служебных полей**
   - Поле __v автоматически исключается
   - Поля с select: false добавляются в список игнорируемых

### Паттерн Singleton

SchemaVault реализован как Singleton — создаётся только один экземпляр реестра, который экспортируется и используется во всём приложении. Это гарантирует консистентность данных о схемах.

## Взаимодействие компонентов

1. **Инициализация приложения**
   - Запуск SchemaVault и регистрация всех моделей
   - Создание реестра схем через config/schema.ts

2. **Обработка запроса**
   - Query.ts получает HTTP-запрос
   - Извлекает модель из реестра SchemaVault
   - Использует метаданные для построения запроса
   - Применяет билдеры и агрегации

3. **Возврат ответа**
   - SendData формирует стандартизированный ответ
   - Логирование через Logger
   - Отправка клиенту

## Преимущества архитектуры

1. **Масштабируемость** — добавление новой сущности требует только регистрации модели
2. **Универсальность** — единый API для всех операций с данными
3. **Гибкость** — поддержка как простых, так и сложных запросов
4. **Типобезопасность** — TypeScript обеспечивает проверку типов на этапе компиляции
5. **Автоматизация** — минимизация ручного кода благодаря метаданным

## Технологический стек

- **Runtime**: Node.js
- **Язык**: TypeScript
- **Фреймворк**: Express.js
- **База данных**: MongoDB
- **ODM**: Mongoose
- **Аутентификация**: JWT (jsonwebtoken)
- **Хеширование**: Argon2
- **Загрузка файлов**: express-fileupload
- **Логирование**: кастомный Logger
